# 本次会话需求与修改记录

## 1. 引擎黑方得分修正

**问题**：引擎分析得分在黑方走子时显示反了。

**原因**：引擎（UCCI/Xiangqi）和 chessdb.cn 云数据库的得分都是从**红方固定视角**返回的（正值 = 红优，负值 = 黑优），但代码错误地按照"走子方视角"进行了转换，导致黑方走子时分数被多取反了一次。

**修改文件**：
- `lib/services/uci_engine.dart` — `EngineInfo.adjustedScore` 改为直接返回 `score`，不再按走子方取反
- `lib/services/cloud_db.dart` — `CloudQueryResult.parseResponse()` 移除 `isRedToMove` 分数转换逻辑

**修改前**：
```dart
int get adjustedScore => isRedToMove ? score : -score;  // ❌
```

**修改后**：
```dart
int get adjustedScore => score;  // ✅ 红方固定视角
```

## 2. 着法列表导航时保留完整招法

**问题**：点击历史着法回退到某个局面时，着法列表只显示到当前局面，后续的招法被"截断"消失了。

**原因**：`MoveHistoryPanel` 使用 `vm.movesFromRoot`（从根到当前节点的路径），回退导航后该路径变短。

**修改**：
- `lib/models/game_tree.dart` — 新增 `mainLineMoves`（完整主变招法列表）和 `mainLinePath`（完整主变节点路径）getter，不受 `_current` 导航位置影响
- `lib/viewmodels/game_viewmodel.dart` — 新增 `mainLineMoves` 和 `mainLineNotations` getter
- `lib/screens/game_screen.dart` — `MoveHistoryPanel` 改用 `vm.mainLineMoves` 和 `vm.mainLineNotations`

**效果**：无论导航到哪个局面，着法列表始终显示完整主变线，仅高亮当前局面。

---

## 3. 着法列表添加首行初始局面

**需求**：着法列表最前面显示初始局面入口，点击可回到开局布局。

**实现**：
- `lib/widgets/common/move_history_panel.dart` — 新增 `onTapRoot` 回调，新增 `_buildRootRow()` 方法
- 首行居中显示 `===` 表示开局
- 点击首行调用 `vm.goToStart()` 回到初始局面
- `currentIndex == -1` 时表示选中首行

---

## 4. 着法列表改为一招一行

**需求**：原来红黑两招并排一行，改为每招单独一行。

**实现**：
- `lib/widgets/common/move_history_panel.dart` — 重写 `_buildMoveList()` 和 `_buildMoveRow()`
- 红方招法（第 1、3、5...个）显示回合编号：`1.`、`2.`、`3.`
- 黑方招法（第 2、4、6...个）不显示编号，仅缩进显示招法文本
- 行高从 `40.0` 调整为 `36.0`

**效果**：
```
===
1. 炮二平五
   马8进7
2. 马二进三
   车9平8
```

## 5. 首行样式调整

**需求**：首行不显示 `0.` 编号，改为居中显示 `===`。

**修改**：`_buildRootRow()` 从 Row 布局改为 `Center` 布局，文本从 `==` 改为 `===`。
