# 得分统一换算需求文档

## 需求概述

为了统一显示红黑双方的走法评估得分，所有分数（引擎分析得分、云数据库得分）都需要**统一换算成红方视角的得分**。

## 核心规则

### 得分换算原则

| 当前走子方 | 原始得分含义 | 换算规则 | 换算后含义 |
| :--- | :--- | :--- | :--- |
| **红方** | 正值 = 红优 | **不变** | 正值 = 红优 |
| **黑方** | 正值 = 黑优 | **取反**（`score = -score`） | 正值 = 红优 |

### 关键洞察

> **黑方的最优选择 = 红方的最差结果**

当轮到黑方走子时，引擎返回的正分表示对黑方有利，这对红方来说就是劣势。因此需要取反来统一成红方视角。

## 当前实现状态

### 引擎得分（`EngineInfo`）

- **文件**: `lib/services/uci_engine.dart`
- **现状**: 
  - `score` 字段注释: `positive = side to move advantage`（正值 = 当前走子方优势）
  - `adjustedScore` getter 存在但**未实际换算**: `int get adjustedScore => isMate ? score : score;`
  - 注释说要转成红方视角，但实现没有做任何转换

### 引擎管理器（`EngineManager`）

- **文件**: `lib/services/engine_manager.dart`
- **现状**: 
  - `getCurrentScore()` 直接返回 `best.score`，没有进行视角转换
  - 注释写的是 `Positive = red advantage`，但实际返回的是走子方视角

### 云数据库得分（`CloudQueryResult`）

- **文件**: `lib/services/cloud_db.dart`
- **现状**: 
  - 解析 chessdb.cn 返回的 `score` 字段
  - chessdb.cn 的得分也是从**当前走子方视角**返回的
  - 目前没有进行红方视角转换

### 得分显示（`ScoreDisplay`）

- **文件**: `lib/widgets/common/analysis_panel.dart`
- **现状**: 
  - 直接使用传入的 `score` 值
  - 颜色编码: 绿色 = 红优（正值），红色 = 黑优（负值）
  - 如果传入的分数没有提前转换，显示的颜色会错误

## 需要修改的位置

### 1. `EngineInfo.adjustedScore`（核心换算逻辑）

**文件**: `lib/services/uci_engine.dart`

需要将 `adjustedScore` 实现为真正的红方视角转换。但问题在于 `EngineInfo` 本身不知道当前是谁走子。

**方案**: 在创建 `EngineInfo` 时传入当前走子方信息，或者在调用方进行转换。

### 2. `EngineManager.getCurrentScore()`

**文件**: `lib/services/engine_manager.dart`

需要在返回分数前进行视角转换。需要知道当前 FEN 中的走子方。

### 3. `CloudQueryResult.parseResponse()`

**文件**: `lib/services/cloud_db.dart`

解析云数据库结果时需要知道当前走子方，并对得分进行转换。

### 4. `ScoreDisplay` 组件

**文件**: `lib/widgets/common/analysis_panel.dart`

确保显示的颜色与换算后的得分一致：
- 正值（红优）: 绿色
- 负值（黑优）: 红色/橙色

## 技术实现要点

### 获取当前走子方

从 FEN 字符串中提取走子方信息：
- FEN 格式: `<board> <active_color> ...`
- `active_color` 为 `'r'` 表示红方，`'b'` 表示黑方

```dart
// 示例代码
bool isRedToMove(String fen) {
  final parts = fen.split(' ');
  if (parts.length < 2) return true; // 默认红方
  return parts[1].toLowerCase() == 'r';
}
```

### 换算逻辑

```dart
/// 将引擎得分转换为红方视角
/// [score] 原始得分（正值 = 走子方优势）
/// [isRedToMove] 当前是否红方走子
/// 返回: 红方视角得分（正值 = 红优）
int convertToRedPerspective(int score, bool isRedToMove) {
  return isRedToMove ? score : -score;
}
```

### 杀棋得分处理

杀棋得分（mate）也需要转换：
- `M3` 表示3步杀
- 如果原始 `score > 0` 表示走子方可以杀对方
- 转换后: 红方能杀 → 正值，黑方能杀 → 负值

## 影响范围

### 需要更新的组件

1. **引擎分析面板** - 显示多行 PV 线的得分
2. **云数据库面板** - 显示候选着法的得分
3. **棋盘走法提示** - 显示最佳着法的得分
4. **对局记录** - 可能显示每步棋的评估变化

### 不需要修改的部分

- 引擎通信协议（UCI/UCCI）- 引擎仍然按走子方视角返回
- 内部着法表示（ICCS 格式）- 不受得分影响
- FEN 解析 - 只读取走子方信息

## 验收标准

- [x] 红方走子时，得分显示与原始引擎输出一致
- [x] 黑方走子时，得分显示为原始引擎输出的相反数
- [x] 所有颜色编码正确反映红方视角（绿=红优，红=黑优）
- [x] 云数据库得分与引擎得分使用统一的红方视角
- [x] 杀棋得分也正确转换
